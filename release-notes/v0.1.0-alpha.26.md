# Wodra v0.1.0-alpha.26

- FE-C connection readiness now follows identified live telemetry (pages 16 and 25); a missing page-54 capability response no longer causes a 40-second timeout after telemetry is already present.
- Capability support remains unknown until a valid page 54 arrives. Wodra uses a labelled compatibility attempt when unknown and blocks simulation only when a valid response explicitly says it is unsupported.
- Rider/bike configuration is sent before the first route-grade control. FE-C commands and capability requests are serialized.
- The client no longer polls and waits for page 71 after every control. Transport acknowledgement, any trainer-reported status, and physical resistance verification are shown as distinct evidence.
- Bluetooth FTMS, profile/key setup, rider settings, route behavior and recording remain unchanged.

Regression coverage exercises the production session-state/control sequence through simulated transport events. The owner has not yet retested alpha.26 on the ANTUSB-m and Flux 2. The supplied alpha.25 logs established identity and telemetry, but not control. Resistance change, disconnect/reconnect and power-cycle recovery remain unverified; #3 and #4 remain open.
