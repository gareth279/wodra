# Wodra v0.1.0-alpha.20

## ANT+ FE-C discovery fix

- FE-C discovery now listens on the ANT channel response callback used by the ANT PC SDK for received broadcast frames. The previous callback only delivered device and protocol responses, so valid trainer pages were never reaching the discovery filter.
- Parses standard broadcast frames and extended frames with channel identity, applies SDK-compatible device type and pairing-bit decoding, and records bounded receive counts by message ID, callback source, extension flag, payload length, page, and rejection reason.
- Callback failures are reported by exception type without logging ANT payloads or network-key bytes. Bluetooth trainer behavior is unchanged.

## Verification status

- ANT PC SDK 3.5 source confirms that channel transmission messages are dispatched to `ANT_Channel.channelResponse`; device protocol messages are dispatched to `ANT_Device.deviceResponse`.
- Regression coverage exercises SDK-format `0x4E` flagged extended broadcasts and `0x5D` extended broadcasts, source identity matching, device-type rejection, and bounded diagnostic aggregation.
- The current host has no SDK-enumerated ANT device. Flux 2 discovery, telemetry, resistance acknowledgement, and recovery after this fix still require owner hardware acceptance. Issues #3 and #4 remain open.
